# Shopping Cart MCP App

Учебное MCP-приложение на TypeScript, React и Skybridge 2.1.0: каталог
Supabase, подробности товаров, корзина и планирование покупок.

## Этап 1: Scenario Modeler

Планировщик сравнивает три набора из уже загруженного каталога, показывает
состав по категориям, стоимость, остаток или дефицит и объясняет рекомендацию.
Бюджет и категории пересчитываются локально, без новых MCP Tools и запросов.

Изменённые файлы:
- `src/lib/scenario-modeler.ts` — чистый расчёт, разбор бюджета, денежные суммы
  в центах, недостающие категории и выбор рекомендации.
- `src/components/ScenarioPlanner.tsx` — ввод и отображение, состояния ошибок
  и пустого каталога, описание стратегий и рекомендованный набор.
- `src/lib/scenario-modeler.test.ts` — 13 автоматических тестов на `node:test`,
  запускаемых через существующий `tsx`, без дополнительных зависимостей.
- `PROJECT_NOTES.md` — решения, проверки и ограничения этапа.

## Правила и Code Review

1. Из каждой уникальной выбранной категории берётся один товар. Сортировка
   по цене, затем по `id`; `filter` создаёт новый массив, каталог не изменяется.
2. `economy` берёт первый товар, `balanced` — средний по порядку цен (нижний
   из двух средних при чётном количестве), `premium` — последний.
3. Рекомендуется самый дорогой доступный из этих трёх наборов. При равной
   стоимости приоритет: economy, balanced, premium. Это правило ценового
   уровня, а не оценка качества или оптимизация всех возможных сочетаний.
4. Цена каждого товара округляется до ближайшего цента десятичным сдвигом;
   сложение, сравнение и остаток используют целые центы. `Math.floor` применяется
   только к индексу среднего товара. Регрессия `10.075 → 1008` покрыта тестом.
5. Бюджет допускает точку/запятую и до двух дробных знаков. Пустое значение,
   ноль, отрицательные числа, текст, экспоненциальная запись и небезопасные
   целые значения центов отклоняются; бюджет не округляется молча.
6. Если категория пуста, доступные товары остаются видимыми, но стоимость
   подписана как частичная. Рекомендация и оценка бюджета отсутствуют.
   При недостаточном бюджете полный состав сохраняется и дефицит показывается.

Из [официального Scenario Modeler](https://github.com/modelcontextprotocol/ext-apps/tree/main/examples/scenario-modeler-server)
адаптирован подход: интерактивные параметры, локальные `useState`/`useMemo`,
сравнение сценариев по одинаковым метрикам и отдельные чистые вычисления
(`src/mcp-app.tsx`, `src/lib/calculations.ts`). Стратегии покупок, рекомендация
и центы — предметная логика этого проекта; SaaS-модель и графики не переносились.

## Проверки

- `node --import tsx --test src/lib/scenario-modeler.test.ts` — 13/13 успешно:
  стратегии, бюджеты и их границы, пустые/неполные данные, точность, отсутствие
  мутаций, порядок при равных ценах и неверный ввод.
- `node_modules\.bin\tsc.cmd --noEmit` — успешно.
- `npm.cmd run build` — успешно, код завершения 0; выходные артефакты проверены.
  Первый запуск ограничивала песочница на этапе упаковки esbuild; повторный
  локальный запуск с разрешённым доступом завершился успешно.
- Отдельная проверка SSR через `react-dom/server` — полный набор, пустой
  каталог и превышение бюджета отображаются корректно. Это не браузерный E2E.
- `npm.cmd run evals:types` — существующая ошибка в `evals/start.eval.ts:10`:
  тест ожидает MCP Tool `start`, которого нет в текущем сервере. Файл не менялся;
  модельный eval с внешним API не запускался.

## Ограничения и оставшаяся проверка

Проверить взаимодействие в реальном MCP-хосте: сменить бюджет на точную стоимость
каждого набора и на цент меньше, ввести пустое/нулевое/отрицательное/текстовое
значение, снять все категории и выбрать несколько снова. В Network убедиться,
что смена параметров не вызывает запросов к backend.

Используются только загруженные товары (существующий `get-products` ограничен
20 позициями), один товар на категорию, конечные неотрицательные цены каталога
обычного денежного диапазона. Доставка, налоги, количество и качество не учитываются.
Для старого onboarding eval требуется отдельная задача. Budget Allocator остаётся
следующим этапом. Сервер, контракты Tools, Supabase, README и зависимости не менялись.
Коммиты, push и deploy не выполнялись.

## UX: сворачиваемый планировщик

В `src/views/products.tsx` планировщик по умолчанию скрыт. Кнопка
«Спланировать покупки» открывает его и меняет подпись на «Скрыть планировщик».
Обёртка использует `hidden`, поэтому компонент остаётся смонтированным:
бюджет и выбранные категории сохраняются при скрытии и повторном открытии
в текущем представлении. Перезагрузка страницы сбрасывает локальное состояние.
Кнопка связана с областью через `aria-controls` и сообщает состояние
через `aria-expanded`. Расчёты, их тесты, MCP Tools и Supabase не изменялись.

Ручная проверка: открыть каталог, раскрыть планировщик, изменить бюджет и
категории, скрыть и открыть снова — значения должны сохраниться.

После UX-изменения `node_modules\.bin\tsc.cmd --noEmit` и `npm.cmd run build`
завершились успешно (код 0). Проверка кликов в браузере не выполнялась.
